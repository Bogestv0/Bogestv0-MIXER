# Этап 6: драйвер Windows

## Часть 6.1: связь движка с драйвером (готово)
Драйвер и движок обмениваются звуком через общую память с кольцевыми буферами. Код: `engine/shm.h` (раскладка памяти и правила обмена описаны в его шапке), подключение к микшеру: `engine/serve.h`.

- **Входы** (драйвер → движок): шесть колец, это «Bogestv0 Input 1–6», то есть дорожки V1–V6. Дорожка берёт звук оттуда, когда драйвер открыл поток и у дорожки выключен тест-источник.
- **Выходы** (движок → драйвер): два кольца, шины B1 и B2, то есть «Bogestv0 Output 1–2» (их видят OBS и Discord как микрофоны). Движок пишет в кольцо, только пока драйвер держит его открытым.
- Формат: 32-битные числа с плавающей точкой, 2 канала, 48 кГц, кольцо на 8192 кадров (~170 мс).
- Каждая сторона шлёт «пульс» (`engine_beat`, `driver_beat`). Окно получает в `state` поле `drv`: память открыта, драйвер жив, какие устройства открыты.
- Нет драйвера или память не открылась: микшер работает как раньше, на тест-источниках.

## Как проверить (Windows, без драйвера)
1. Скачайте `engine.exe` из последней сборки Engine (Actions → Engine → Artifacts).
2. В одном окне командной строки: `engine.exe --serve` (или запустите сам микшер).
3. Во втором: `engine.exe --fake-driver 15`.
   - Должна появиться строка «Имитация драйвера подключена (Global\Bogestv0MixerAudio…)». Если написано `Local\…`, Windows не дала создать `Global\`; для 6.1 это нормально, но для настоящего драйвера нужно решение (см. ниже).
   - Каждую секунду строка «engine_beat … из B1 пришло, пик … дБ». Если на «Музыке» (V2) включён маршрут B1, пик около −10,5 дБ (тон 0,3).
   - Чтобы услышать тон: в микшере у «Музыка» выключите тест-источник и включите маршрут на A1 или A2.
4. `engine.exe --selftest` должен закончиться «Все проверки пройдены» (его запускает и сборка Engine, и Release).

## Что проверено без Windows
- `--selftest`: кольца (порядок, нехватка, переполнение, переход позиции через границу 2³², испорченные позиции), два потока с 400000 кадрами без потерь, второй движок получает отказ, перезапуск движка сохраняет память, весь путь V2 → B1 на «нулевом» звуковом бэкенде, приоритет тест-источника, остановка записи в закрытый выход.
- То же под ThreadSanitizer: гонок нет.
- Два отдельных процесса (`--serve` и `--fake-driver`): состояние `drv` меняется на `alive:1`, `in:[0,1,0,0,0,0]`, `out:[1,0]`, тон возвращается из B1.

## Что не проверено (нужен Windows)
- Windows-ветка `shm.h` (`CreateFileMapping`, права доступа) здесь не собиралась. Если сборка Engine в GitHub Actions выдаст ошибку, пришлите текст.

## Решено и открыто для 6.2
1. **Кто создаёт память. РЕШЕНО (30.10.2026): вариант (а).** Сейчас её создаёт движок (обычный процесс пользователя), а драйвер должен её открыть. Но драйвер ядра (и звуковая служба Windows) работают вне сеанса пользователя, а создать `Global\` без особой привилегии обычный процесс не может. Варианты: (а) память создаёт драйвер и отдаёт движку через запрос к своему устройству (IOCTL), это самый надёжный путь; (б) память создаёт служба, запущенная от системы; (в) для тестового режима давать права на `Global\` вручную. Выбран (а): память создаёт драйвер, движок спрашивает её у устройства драйвера. Тогда `Shm::open` в движке превратится в «спросить у драйвера» (раскладка колец и правила остаются теми же). Пока драйвера нет, нынешний вариант (движок создаёт память сам) остаётся для проверок и `--fake-driver`; в 6.4 он станет запасным.
2. **Частота.** Раскладка хранит частоту (48000). Выбор 44100 / 48000 на экране «Дорожки и аудио» и пересчёт между частотами драйвера и движка делаем в 6.6.
3. **Часы.** У драйвера и у движка свои такты; расхождение движок сглаживает обрезкой запаса (как у остальных устройств). Щелчки на длинной дистанции проверим в 6.5–6.6.
4. **Нет ведущего устройства.** Движок обрабатывает звук только пока открыто хотя бы одно устройство A/B. Без него драйвер получает тишину. Если это неудобно (например, только B1 для OBS), в 6.4 можно добавить такт «по таймеру».

- **Лицензия SysVAD: MS-PL, а не MIT** (в первой версии README была ошибка). См. `driver/UPSTREAM.md`.

### 6.2b: число устройств 6 + 2 (собирается)
`driver/patch_sysvad.py` теперь делает три шага (каждый обязан сработать ровно один раз, иначе остановка с понятным сообщением):
1. **INF, имена** (6.2a): 19 строк.
2. **INF, новые устройства**: для «Bogestv0 Input 5» и «Input 6» добавлены разделы интерфейсов, строки `AddInterface` и имена в `[Strings]` (`KSNAME_WaveInput5`, `…TopologyInput5` и т. д.).
3. **`minipairs.h` (C++)**: две новые пары `BogestvInput5/6Miniports` добавлены в `g_RenderEndpoints` (воспроизведение 4 → 6); из `g_CaptureEndpoints` убраны массивы микрофонов 2 и 3 (запись 4 → 2: «Output 1» = MicIn, «Output 2» = MicArray1).

Как устроены новые устройства: это копии пары SPDIF (те же таблицы форматов и описатели фильтров, свои имена подустройств `WaveInput5`/`TopologyInput5`). SPDIF выбран за простоту: у него нет списка аудио-модулей, который пришлось бы дублировать. Число подустройств осталось прежним (16), лимит `g_MaxMiniports` считается сам.

Что я проверил: скрипт на настоящем SysVAD (коммит `f4c1ff8…`), повторный запуск, кодировки и переводы строк (INF остаётся UTF-16 с BOM, `minipairs.h` без BOM, CRLF сохранён). Сборка на Windows прошла. Не проверено: установка INF и то, как устройства выглядят в Windows (это 6.3).

Сознательные оговорки:
- Устройства Input 5–6 унаследовали от SPDIF форматы 16 бит, 44,1–96 кГц. Для нас это не страшно: Windows миксует в своём формате, а перевод в формат колец движка (float32, 48 кГц) делается в 6.4/6.6.
- В INF остались разделы микрофонов 2 и 3 (без C++-пары они никогда не включатся и ничему не мешают). Уберём, когда подтвердится, что всё собирается.
- Видимые в Windows имена («Динамики (Bogestv0 Input 1)» или иначе) смотрим в 6.3 на установленном драйвере.

Первый запуск 6.2b упал на INF: скрипт не добавил строки имён Input 5–6 в `[Strings]` (ошибка в его проверке «уже применено»). Исправлено, добавлена самопроверка «все используемые имена определены».

### Что в 6.2a сознательно не сделано и почему
- **Число устройств** (в 6.2a): в SysVAD 4 устройства воспроизведения и 4 записи, нам нужно 6 + 2. Это сделано в 6.2b (см. выше).
- **Видимые имена в Windows.** Имена в INF задают имена фильтров. То, как устройство называется в списке звука Windows («Динамики (Bogestv0 Virtual Audio)»), зависит ещё от описания устройства и имён контактов в таблицах на C++. Окончательные «Bogestv0 Input 1» доводим по тому, что покажет Windows (в 6.3, после установки).
- **Подпись.** Сборка использует тестовую подпись WDK. Если шаг подписи на CI не пройдёт (нужен сертификат), в 6.3 добавим создание тестового сертификата.
- **Передача звука.** Пока драйвер это SysVAD: он играет тон и записывает в файл, но звук в движок не отдаёт. Подключение к общей памяти (создаёт драйвер, движок получает через IOCTL) это 6.4.

### 6.2c: имена устройств воспроизведения (написано, не собиралось)
Итог первой установки (30.10.2026): Windows увидела 6 устройств воспроизведения и 2 записи, но воспроизведение назвала по типу разъёма («Динамики», «Наушники», «SinkDescription Sample», три «Интерфейс SPDIF»), а записи получили правильные имена «Bogestv0 Output 1/2». Причина: имя конечной точки берётся не из INF, а из «имени» (GUID) контакта-выхода в таблице топологии плюс строки в реестре; у микрофонов это уже было сделано.

Что делает 6.2c: каждому из шести устройств воспроизведения ставит своё имя «Bogestv0 Input N» (GUID в таблице топологии + регистрация в INF). Для Input 5 и 6 скрипт создаёт копии таблицы SPDIF (`bogestvin5toptable.h`, `bogestvin6toptable.h`), иначе три SPDIF-устройства делили бы одно имя. Неясно, переопределит ли имя HDMI-устройство (его имя берётся из описания монитора): проверяем после установки.

**Переустановка после новой сборки** (в PowerShell от администратора):
1. `pnputil /remove-device /deviceid "Root\Sysvad_ComponentizedAudioSample"`
2. `pnputil /enum-drivers`, найти пакет с поставщиком Bogestv0 (например oem131.inf), затем `pnputil /delete-driver oem131.inf /uninstall /force`
3. Распаковать новый артефакт в `C:\bogestv0-driver`, затем `certutil -addstore Root package.cer` и `certutil -addstore TrustedPublisher package.cer` (сертификат новый), `pnputil /add-driver ComponentizedAudioSample.inf /install`, `powershell -ExecutionPolicy Bypass -File install-device.ps1`.
4. **Сразу после установки** вернуть устройства по умолчанию на Realtek (Windows сама назначает наши).

**Результат установки (30.10.2026, Windows 11 26200, тестовый режим):** драйвер ставится, в Диспетчере устройств «Bogestv0 Virtual Audio» без ошибок, видны 6 устройств воспроизведения и 2 записи. Имена, которые драйвер задаёт сам: **Input 2, 4, 5, 6 и Output 1, 2 работают**. **Открыто:** «Input 1» (динамики) и «Input 3» (HDMI) в Windows остались «Динамики (Bogestv0 Virtual Audio)» и «SinkDescription Sample»; правки 6.2c для них (тип разъёма динамиков, строка описания монитора HDMI) эффекта не дали или не подтверждены, на тестовой машине эти два устройства переименованы вручную. Вернуться к этому до выпуска (этап 8). Идеи: у Input 1 менять не только тип разъёма, но и тип соединения (`eConnTypeUnknown`); для HDMI проверить, откуда берётся имя (описание монитора, кэш конечной точки).

**Важно при тестировании:** Windows сама назначает наши устройства устройствами по умолчанию (воспроизведение и запись) после каждой установки. Сразу после установки вернуть Realtek.

## Часть 6.3: установка драйвера в тестовом режиме (скрипты написаны, не запускались на Windows)
**Цель:** поставить драйвер одной командой, увидеть шесть устройств воспроизведения и два записи, убрать драйвер, если что-то не так. Звука драйвер пока не передаёт (это 6.4): играет тон и пишет в файл, как обычный SysVAD.

Ручная установка из 6.2c уже работала (30.10.2026, Windows 11 26200). 6.3 превращает её в скрипты, которые лежат в Artifacts рядом с `.sys` и `.inf`: `install.ps1` и `uninstall.ps1` (исходники в `driver/`). Скрипт `install-device.ps1`, упомянутый раньше, в репозитории не лежал; `install.ps1` его заменяет (создаёт устройство тем же способом, что `devcon`, через SetupAPI, WDK не нужен).

### Где ставить
Лучше на **виртуальной машине** (снимок состояния перед установкой) или втором компьютере. Драйвер ядра с ошибкой может вызвать синий экран, тестовый режим снижает защиту системы.

### Подготовка (один раз)
1. **Secure Boot выключен**, иначе тестовый режим не включится (Hyper-V, 2-е поколение: Параметры → Безопасность → снять «Включить безопасную загрузку»).
2. Точка восстановления или снимок ВМ.
3. PowerShell **от имени администратора**: `bcdedit /set testsigning on`, перезагрузка. В углу рабочего стола появится «Тестовый режим».
4. Скачать Artifacts `bogestv0-driver-x64` последней зелёной сборки Driver и распаковать в папку без пробелов, например `C:\bogestv0-driver`.

### Установка и переустановка
В той же папке, PowerShell от администратора:
```
powershell -ExecutionPolicy Bypass -File install.ps1
```
Скрипт проверяет права и тестовый режим, добавляет `package.cer` в хранилища Root и TrustedPublisher, ставит пакет (`pnputil /add-driver … /install`) и создаёт устройство `Root\Sysvad_ComponentizedAudioSample`. Повторный запуск безопасен: устройство не дублируется, драйвер обновляется. **Для новой сборки** сначала `uninstall.ps1`, потом распаковать новый артефакт и `install.ps1` (сертификат в каждой сборке новый).

Ставится только базовый `ComponentizedAudioSample.inf`; APO и расширение не нужны.

**Сразу после установки** Windows назначает наши устройства по умолчанию: верните свои колонки и микрофон (Параметры → Звук).

### Что проверить и прислать
1. Диспетчер устройств → «Звуковые, игровые и видеоустройства»: «Bogestv0 Virtual Audio» без жёлтого значка (иначе пришлите код ошибки из Свойств).
2. Параметры звука: вывод, шесть устройств; ввод, два «Bogestv0 Output 1–2». Скриншот обоих списков.
3. Выберите «Input 1» по умолчанию и запустите звук: тишина без ошибок. Если синий экран, пришлите имя ошибки и файл.
4. Если `install.ps1` остановился, пришлите строку «ОШИБКА: …» целиком.

### Удаление
`powershell -ExecutionPolicy Bypass -File uninstall.ps1` убирает устройство и все пакеты драйвера с поставщиком Bogestv0 (поиск через `Get-WindowsDriver`, не зависит от языка Windows). Сертификат и тестовый режим остаются: `bcdedit /set testsigning off` и перезагрузка. Если система не грузится: снимок или точка восстановления.

### Возможные сюрпризы
- «Драйвер не подписан»: не включён тестовый режим или сертификат не попал в оба хранилища (скрипт проверяет и то и другое).
- «INF не подходит этой версии Windows»: пришлите точный текст.
- Скрипты не запускались на Windows (здесь нет ни Windows, ни PowerShell): первая ошибка возможна, присылайте текст.

### Открыто из 6.2c (до выпуска, этап 8)
«Input 1» (динамики) и «Input 3» (HDMI) в Windows называются не по-нашему: у Input 1 менять не только тип разъёма, но и тип соединения (`eConnTypeUnknown`); у HDMI выяснить, откуда берётся имя (описание монитора, кэш конечной точки).
