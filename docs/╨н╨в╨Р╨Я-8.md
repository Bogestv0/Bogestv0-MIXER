# Этап 8. Выпуск: что сделано и что нужно от вас

## Сделано
- **8.1 Установщик с драйвером** (с 0.4.0): приложение, движок и драйвер в одном `setup.exe`. По вашим словам, установка и обновление работают.
- **8.2 Автозапуск** (0.5.8): «Настройки → Запускать вместе с Windows». Значение `Bogestv0 MIXER` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, запуск с ключом `--autostart`: окно не показывается, микшер сразу в трее (если значок в трее выключен, окно показывается всегда, иначе его не открыть). Состояние переключателя читается из реестра, поэтому выключение в «Диспетчере задач → Автозагрузка» тоже учитывается. При настоящем удалении программы ключ убирается (`uninstall.ps1 -Auto`), при обновлении остаётся.
- **8.2 Обновление драйвера отдельно и реже**: уже работает. `install.ps1 -Auto` сравнивает SHA-256 файлов драйвера с последней удачной установкой (`%ProgramData%\Bogestv0\driver.sig`): если драйвер не менялся, обновление микшера его не трогает; если менялся, он переустанавливается начисто.
- **8.3 Заготовки под подпись** (всё выключено, пока нет сертификатов):
  - `release.yml`: шаг «Подпись приложения» включается, если в секретах репозитория есть `WINDOWS_CERTIFICATE` (файл `.pfx` в base64) и `WINDOWS_CERTIFICATE_PASSWORD`. Без них релиз выходит как раньше.
  - `driver/install.ps1`: если рядом лежит пустой файл `attested.flag`, скрипт не включает тестовый режим и не ставит наш тестовый сертификат (драйвер подписан Microsoft).

## Нужно от вас (8.3)
1. **Подпись приложения (убирает предупреждение SmartScreen).** Купить сертификат подписи кода (OV или EV) у удостоверяющего центра. Если сертификат выдан в виде файла `.pfx`: `base64 -w0 cert.pfx` (или `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx"))`) положить в секрет `WINDOWS_CERTIFICATE`, пароль в `WINDOWS_CERTIFICATE_PASSWORD`. Многие EV-сертификаты выдают на аппаратном ключе или в облаке без выгрузки `.pfx`: тогда этот шаг не подойдёт, нужен другой способ (например, облачная подпись), его надо будет подключить отдельно.
2. **Подпись драйвера (убирает тестовый режим).** Нужен аккаунт Microsoft Partner Center (Windows Hardware Dev Center), для которого требуется EV-сертификат подписи кода. Порядок по документации Microsoft («attestation signing»): `.cab` с драйвером и INF уже собирает `driver.yml` (артефакт запуска `bogestv0-driver-attestation`, файл `Bogestv0Driver-attestation.cab`); его нужно подписать EV-сертификатом (`signtool sign` на `.cab`), отправить в Partner Center, скачать подписанный пакет. Состав `.cab` и требования к нему сверьте с документацией Microsoft: шаг сборки я не мог запустить. Этот путь ручной, автоматизировать его в GitHub Actions можно позже. Подписанный пакет кладётся в `src-tauri/driver` вместе с пустым `attested.flag`. Точные шаги и требования сверьте с актуальной документацией Microsoft: я не мог проверить их из этой среды.

## Проверка 8.4 (чистая установка)
На другом компьютере (или в виртуальной машине) без тестового режима и без следов микшера:
1. Установить `Bogestv0 MIXER_…_x64-setup.exe`. Для неподписанного драйвера Windows один раз попросит перезагрузку (тестовый режим), для подписанного не нужно.
2. Убедиться: в «Параметры → Звук» есть `Bogestv0 … In/Out`; микшер видит «Драйвер работает»; в «Настройки → Запускать вместе с Windows» включить, выйти из системы и войти: микшер в трее, звук работает.
3. Обновить с предыдущей версии: настройки на месте, драйвер без нужды не переустанавливается (журнал `driver-setup.log`: «Ничего не делаю»).
4. Удалить: исчезли устройства, программа и автозапуск; тестовый режим остаётся (`bcdedit /set testsigning off`).

## Бесплатный путь (проверено по документации, на практике не пробовалось)
**Приложение: SignPath Foundation.** Бесплатная подпись для открытых проектов. Условия: OSI-лицензия (стоит MIT, файл `LICENSE`), публичный репозиторий, бесплатные бинарники в GitHub Releases, сборка в публичном CI. В репозитории для заявки уже есть `LICENSE`, `THIRD_PARTY_NOTICES.md`, `CODE_SIGNING.md`, README и публичный `release.yml`. Что сделать вам:
1. Подать заявку на сайте SignPath Foundation (signpath.org): ссылка на репозиторий, лицензия MIT, ссылка на страницу релизов, описание (лучше по-английски), почта для связи. Срок рассмотрения неизвестен, возможны уточняющие вопросы.
2. После одобрения SignPath даст инструкцию по подключению к GitHub Actions. Тогда в `release.yml` вместо шага «Подпись приложения (если есть сертификат)» добавляется шаг отправки установщика на подпись в SignPath (я сделаю это, когда будут их параметры: идентификатор организации, проекта, политики подписи и токен в секретах). Подпись SignPath ставится на готовый установщик и файлы в нём.
3. SmartScreen после подписи уходит не сразу: репутация копится с релизами.
Если вас не одобрят или условия изменятся, остаются платные варианты (см. выше).

**Драйвер: бесплатного пути нет.** Подпись через Partner Center требует EV-сертификата (платный). Пока его нет, драйвер работает в тестовом режиме Windows, как сейчас.
