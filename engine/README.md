# Движок (этапы 2–6)

Консольная программа: микрофон → программное усиление 0…+30 дБ → мягкий ограничитель → наушники. Показывает уровень и оценку задержки.

## Запуск
1. На GitHub: Actions → Engine → последний запуск → Artifacts → `bogestv0-engine-win64`. Распакуйте `engine.exe`.
2. В командной строке: `engine.exe --list` — номера микрофонов и выходов.
3. `engine.exe --in 1 --out 2` — вы слышите себя в наушниках. Клавиши: `+` / `-` усиление, `q` выход.

Опции: `--gain ДБ`, `--period 128|256|512`, `--rate 44100|48000`, `--exclusive` (эксклюзивный режим микрофона, меньше задержка).

**Только в наушниках!** В колонках микрофон начнёт свистеть.

## Устройство
- `main.cpp` — устройства, консольный режим, самопроверка. `dsp.h` — усиление, ограничитель, метр (без выделения памяти в аудио-потоке).
- `serve.h` — режим `--serve`: микшер, которым управляет окно (команды в stdin, ответы JSON в stdout).
- `shm.h` — общая память с драйвером (этап 6.1): шесть колец «драйвер → движок» (V1–V6) и два «движок → драйвер» (B1, B2). Раскладка и правила обмена описаны в шапке файла.
- `mic.h` — обработка микрофона (этап 4): фильтр низких, усиление, шумодав, гейт, компрессор.
- `third_party/rnnoise` — нейросеть шумоподавления RNNoise v0.1.1 (BSD-3), с двумя небольшими правками для Visual C++ (см. `BOGESTV0.txt` в папке).
- `third_party/miniaudio.h` — библиотека miniaudio (общественное достояние / MIT-0), WASAPI.
- Проверка обработки без звука: `engine.exe --selftest` (в том числе шумодав на шуме, гейт, компрессор, фильтр).

## Команды микрофона (режим `--serve`)
`set mic I gain 0..30` · `gate -80..-20` (-80 = выкл) · `hpf 20..300` (20 = выкл) · `comp 1..10` (1 = выкл) · `ns 0..3` (выкл / мягкое / сильное / максимум) · `nsamt 0..100`. I = 0 или 1.
Состояние: поле `mic` в ответе `state`. Уровень фона до и после подавления: поле `n` в ответе `m` (дБ, `[до, после]` для каждого микрофона).

## Шины и устройства (этап 5, режим `--serve`)
`set bus K gain -48..12` · `set bus K mute 0/1` (K: 0..2 = A1..A3, 3..4 = B1, B2). Состояние: поле `buses` в ответе `state`, уровни: поле `b` в ответе `m`.
Сторож устройств работает в отдельном потоке и раз в ~2 секунды проверяет назначенные устройства: остановившееся или пропавшее закрывается, вернувшееся открывается заново (только оно; если пропало ведущее, тракт собирается заново). Неудачные попытки повторяются реже (2, 4, … до 30 секунд), об ошибке сообщается один раз. Когда список устройств в Windows меняется, окно получает новый ответ `devices`.
Проверка без железа: `engine.exe --selftest` (в том числе сторож на «нулевом» звуковом бэкенде miniaudio).

## Драйвер: общая память (этап 6.1)
Движок при запуске создаёт общую память `Global\\Bogestv0MixerAudio` (если Windows не разрешает `Global\\`, то `Local\\Bogestv0MixerAudio`). Драйвер (или его имитация) открывает её и пишет в кольца входов / читает из колец выходов.
- Дорожка V1…V6 берёт звук драйвера, когда драйвер открыл поток на «Bogestv0 Input N» и у дорожки выключен тест-источник. Тест-источник важнее драйвера.
- Шины B1 и B2 кроме устройства пишутся в «Bogestv0 Output 1/2», пока драйвер держит их открытыми.
- Состояние: поле `drv` в ответе `state`: `shm` (память открыта), `alive` (счётчик драйвера идёт), `in` (какие из Input 1–6 открыты), `out` (какие из Output 1–2 открыты). Обновляется сторожем раз в ~2 секунды.
- Если память не открылась, движок работает как раньше (тест-источники) и один раз сообщает об этом в `err`.
- Проверка без драйвера: `engine.exe --selftest` (кольца, два потока, второй движок, перезапуск, весь путь V2 → B1 на «нулевом» бэкенде) и `engine.exe --fake-driver [секунд]` при работающем микшере (тон 440 Гц в Input 2, прослушивание Output 1).
