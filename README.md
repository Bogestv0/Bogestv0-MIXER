# Bogestv0 MIXER — README

Собственный виртуальный аудиомикшер для Windows: свой движок, свои виртуальные устройства, свой интерфейс, обновления через GitHub.
Voicemeeter Banana (VB-Audio) был только **образцом поведения**. Его код и драйверы мы не берём.

Содержание: 0. Где мы сейчас · 1. Что понято из образца · 2. Что понято из интерфейса · 3. Решения · 4. Архитектура · 5. С чего начать и этапы (и «План оставшихся этапов») · 6. Обновления через GitHub · 7. Риски · 8. Открытые вопросы · 9. Файлы в архиве

## 1. Что понято из образца (Voicemeeter)

**Три слоя.** Драйверы (виртуальные звуковые устройства Windows), движок (захват, обработка, маршрутизация, вывод; в одном процессе с окном) и Remote API (канал управления снаружи).

**Сигнальный путь:** входные дорожки → кнопки маршрута A1–A3 / B1–B2 → выходные шины → устройства.
- **A** это физические выходы (колонки, наушники).
- **B** это виртуальные выходы, которые другие программы видят как микрофоны (OBS, Discord).
- На дорожке: фейдер, mute, solo, EQ, компрессор, гейт. На шине: фейдер, mute, EQ. Есть рекордер и эффекты.

**Что берём как идею:** один вход можно слать на любое число выходов; состояние хранит движок, а окно только показывает его и шлёт команды; фейдер −60…+12 дБ, двойной клик сбрасывает на 0 дБ.

**Чего у образца нет и мы делаем сами:** свои названия устройств, 2 микрофона + 4 виртуальных входа, нейросетевое шумоподавление, сцены, саундпад.

Лицензия Voicemeeter запрещает модифицировать и декомпилировать его файлы и встраивать пакет в чужой установщик. Поэтому наш продукт полностью независимый.

## 2. Что понято из интерфейса

Экраны (макеты в `ui/`): **Микшер, Микрофон·шумоподавление, Сцены, Эффекты, Запись, Дорожки и аудио**. Экраны **Выходы, Устройства** и полноценные **Настройки** лежат в `ui/sketch-original/` в старом виде (одна дорожка микрофона), их надо привести к 8 дорожкам.

**Дорожки (8):** Микрофон 1 (HW1), Микрофон 2 (HW2), Игры (V1), Музыка (V2), Discord (V3), Браузер (V4), Донаты (V5), Браузер 2 (V6). У каждой: фейдер −48…+12 дБ, метры L/R, Mute, Solo, кнопки A1 A2 A3 B1 B2. На микрофонах ещё шумодав (Выкл / Мягкое / Сильное / Макс), Гейт и Компр. На виртуальных Бас и ВЧ.

**Кнопки:**
- **Шестерёнка на дорожке** открывает экран «Дорожки и аудио»: переименование (например, «Браузер 2» → «Twitch»), скрытие ненужной дорожки (звук и маршруты остаются, дорожка не показывается на микшере), источник. Имена хранятся в настройках и в сценах.
- **Mute** выключает звук дорожки, фейдер остаётся на месте.
- **Solo** (решено): при нажатии работает только эта дорожка, все остальные отключаются.
- **A1…B2** включают отправку дорожки на этот выход; можно на несколько сразу.
- **Сцена** это режим (например, для стрима): настройки микрофонов, маршруты (куда идёт звук) и какие устройства стоят в слотах. Если маршрут поменяли руками, сцена показывается как «свои настройки».
- **Эффекты (саундпад):** заранее загруженные звуки на кнопках; играют на B1, B2 и/или в наушники (A2), по выбору.
- **Запись:** пишет звук с выбранных выходов. Если выбраны A1 и B1, пишутся оба: раздельными файлами или одним общим. Формат WAV или MP3.

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Основа | Полностью свой движок и свои драйверы, без кода Voicemeeter |
| Входы | 2 железных (микрофоны) + 6 виртуальных (Игры, Музыка, Discord, Браузер, Донаты, Браузер 2). Названия можно менять, ненужные дорожки скрывать |
| Выходы | A1–A3 (физические), B1–B2 (виртуальные микрофоны) |
| Усиление микрофона | **Программное**, 0…+30 дБ, в нашем движке, с защитой от перегрузки. Отдельной звуковой карты нет (звук с материнской платы), поэтому аппаратного усиления в драйвере может не быть |
| Шумоподавление | Нейросеть RNNoise (по моим данным, лицензия BSD, проверить), режимы Мягкое / Сильное / Макс |
| Solo | Эксклюзивный: слышно только одну дорожку |
| Быстрые кнопки усиления | Есть: +0 / +10 / +20 / +30 дБ рядом с ползунком на экране «Микрофон» |
| Оболочка окна | **Tauri** (самая лёгкая по памяти и размеру, пока работают игры и OBS), движок на **C++** отдельным процессом |
| Репозиторий GitHub | `Bogestv0-MIXER` (так же, как называется микшер) |
| Обновления | Через GitHub Releases, микшер сам проверяет и устанавливает (раздел 6) |
| Общая память драйвера (решено 30.10.2026) | **Память создаёт сам драйвер**, а движок получает к ней доступ запросом к устройству драйвера (IOCTL). Движок память не создаёт, раскладка колец (`engine/shm.h`) не меняется. Причина: драйвер и звуковая служба Windows работают вне сеанса пользователя, а обычный процесс не может создать область в `Global\`. |

## 3.1 Аудио-настройки из Voicemeeter: что добавляем

По скриншоту «System settings / Options» из Voicemeeter. Это экран «Дорожки и аудио» (аудио-параметры) и «Выходы» / «Устройства».

**Добавляем:**
| Настройка | У нас |
|---|---|
| Частота (Preferred Main SampleRate) | Выбор 44100 / 48000 Гц, по умолчанию 48000 |
| Буфер (Buffering WDM, 512) | Один пункт «Буфер»: 128 / 256 / 512 / 1024 смп, рядом показана задержка в мс |
| Лимитер выходов (OUT Limiter) | Переключатель, включён по умолчанию |
| Задержка выходов (Monitoring Synchro Delay A1–A3) | Поля в мс для каждого A, для выравнивания звука между колонками и наушниками |
| Состояние устройства (ON / частота / каналы / разрядность) | Строка на экране «Устройства»: «Работает · 48 кГц · 2 канала · 24 бита» |
| Ресемплинг между частотами | В движке: устройства на 44.1 и 48 кГц работают одновременно (у вас так и есть) |
| Эксклюзивный захват микрофона (WDM Input Exclusive Mode) | Переключатель «Низкая задержка микрофона», по умолчанию выключен |

**Не нужны:** отдельные буферы MME / KS / ASIO / Clock (у нас один интерфейс WASAPI), Virtual ASIO Type, VAIO sync (решает наш драйвер), Engine Mode.

**Важно для движка:** названия устройств бывают на разных языках (например, «Динамики (Redmi电脑音箱)»), поэтому везде Unicode. В Voicemeeter у вас есть отдельные дорожки под донаты и игры, поэтому добавлены «Донаты» и «Браузер 2».

## 4. Архитектура

```
┌──────────────────────────┐   команды / события / метры   ┌───────────────────────────┐
│ Оболочка + интерфейс     │ ───────────────────────────▶  │ Движок (отдельный .exe)   │
│ (окно, трей, обновления) │ ◀───────────────────────────  │ C++: WASAPI, DSP, RNNoise │
└──────────────────────────┘     named pipe / WebSocket    └─────────────┬─────────────┘
                                                                         │
                                                      ┌──────────────────┴──────────────┐
                                                      │ Драйвер Windows (виртуальные    │
                                                      │ устройства V1–V4, B1–B2)        │
                                                      └─────────────────────────────────┘
```

- **Движок** это отдельный процесс. Если интерфейс завис или закрылся, звук продолжает работать.
- **Интерфейс ничего не обрабатывает сам:** шлёт команды (`set strip 2 gain -6`), получает состояние и уровни метров (~30 раз в секунду).
- **Хранение:** `bogestv0-settings.json` (маршруты, громкости, сцены, устройства, настройки программы, список звуков саундпада).
- **Обработка дорожки:** усиление → гейт → шумодав → фильтр низких → компрессор → EQ → фейдер → маршрутизация. **Шина:** EQ → фейдер → mute → устройство и/или рекордер.
- **Стек (решено, критерий: эффективность):** движок на **C++** (звук в реальном времени), оболочка на **Tauri** (по моим данным, окно занимает в разы меньше памяти, чем Electron, и есть встроенное подписанное обновление). Для оболочки нужен Rust, но она тонкая: окно, трей, связь с движком, обновления. Если с Tauri возникнут трудности, запасной вариант Electron.

## 5. С чего начать и по этапам

**Начинаем с каркаса и обновлений, а не с движка.** Тогда путь «я изменил код → вы залили на GitHub → микшер сам обновился» заработает с первого дня, а все следующие этапы доезжают до вас так же.

Каждый этап заканчивается проверкой, которую можно сделать руками.

### Этап 0. Подготовка (вы, около часа)
- Аккаунт GitHub и **публичный** репозиторий `Bogestv0-MIXER`. Публичный нужен, чтобы микшер мог проверять обновления без секретного ключа.
- На компьютере: Windows 10/11, Git, Node.js (LTS), Rust (rustup), Visual Studio Build Tools (C++).
- Положить в репозиторий этот архив: `README.md` и `ui/`.
- ✅ *Проверка:* репозиторий открывается, README виден.

### Этап 1. Каркас приложения + обновления
- Окно Tauri с вашими экранами (перенос из `.dc.html` в обычный HTML/JS, по одному экрану), навигация по меню, значок в трее.
- Файл версии (`0.0.1`), `CHANGELOG.md`, сборка установщика `.exe`.
- GitHub Actions: при создании тега `v0.0.1` само собирает установщик и выкладывает Release.
- Проверка обновлений (раздел 6) и блок «Обновления» в Настройках.
- ✅ *Проверка:* установили 0.0.1, выложили 0.0.2, микшер сам предложил обновиться и перезапустился на 0.0.2.

### Этап 2. Движок v0 (консольный, без драйвера)
- Захват микрофона и вывод на наушники через WASAPI, метры, блоки 128–256 сэмплов.
- Быстрый прототип можно собрать на библиотеке miniaudio (по моим данным, общественное достояние), затем перейти на прямой WASAPI, если понадобится.
- ✅ *Проверка:* говорите в микрофон, слышите себя в наушниках, консоль показывает уровень, задержка в пределах 10 мс.

### Этап 3. Движок + интерфейс
- Канал связи движок ↔ окно. Ожили: фейдеры, Mute, Solo (эксклюзивный), кнопки A/B, метры, статус «Движок работает».
- Сцены (хранятся в JSON), устройства и слоты HW1, HW2, A1–A3.

## 6. Обновления через GitHub

### Как это работает
```
Вы говорите мне, что изменить
        ↓
Я готовлю изменённые файлы (в архиве или патче) и запись в CHANGELOG
        ↓
Вы заливаете их в репозиторий GitHub (или это делает Claude Code с доступом к репозиторию)
        ↓
Создаёте тег версии, например v0.3.1
        ↓
GitHub Actions собирает установщик и публикует Release
        ↓
Микшер у вас на компьютере при запуске (и раз в несколько часов) спрашивает GitHub: «есть версия новее?»
        ↓
Показывает окно «Доступно 0.3.1 — что нового» → скачивает → проверяет → ставит → перезапускается
```

В этом чате я не могу сам отправлять файлы в ваш GitHub: у меня нет доступа к вашей учётной записи. Я даю готовые файлы, а загрузка делается вами или через Claude Code, подключённый к репозиторию.

### Что делает микшер
- **При запуске и по таймеру** обращается к GitHub Releases вашего репозитория и сравнивает версию с установленной (формат `1.2.3`).
- **Если версия новее:** показывает уведомление и окно «Что нового» (текст берётся из описания релиза / `CHANGELOG.md`) с кнопками «Обновить сейчас» и «Позже».
- **Скачивает установщик**, проверяет контрольную сумму и подпись, закрывает движок, ставит обновление и запускает новую версию.
- **Сохраняет ваши настройки:** `bogestv0-settings.json` лежит отдельно от программы и при обновлении не трогается.
- **Откат:** если новая версия не запустилась, остаётся старая, а в окне показывается сообщение об ошибке.
- **Подпись обновлений:** у Tauri обновления подписываются отдельным ключом; микшер ставит только то, что подписано вашим ключом. Ключ хранится у вас, не в репозитории.

### Блок «Обновления» в Настройках (добавить в макет)
- Текущая версия и статус («Установлена последняя версия» / «Доступно 0.3.1»).
- Кнопка «Проверить сейчас».
- Переключатели: «Проверять автоматически», «Устанавливать сами при закрытии программы».
- Канал: «Стабильные» или «Тестовые (beta)». Тестовые можно выкладывать для проверки до основного релиза.
- Кнопка «Что нового» (список версий).

### Правила релизов
- Версии по схеме `основная.дополнительная.исправление`: `0.3.1`, `0.4.0`, `1.0.0`.
- Каждый релиз описан в `CHANGELOG.md` простыми словами.
- Тег и версия в файле проекта должны совпадать, иначе сборка не пройдёт.
- Репозиторий публичный. Приватный потребует токен внутри программы, а это небезопасно.

### Ограничения, о которых надо знать
- **Драйвер обновляется отдельно и реже:** ему нужны права администратора и, возможно, перезагрузка. Обновление только интерфейса и движка без драйвера идёт бесшумно.
- **Подпись приложения.** Без сертификата подписи Windows может показывать предупреждение SmartScreen при установке. На этапах разработки это терпимо, к выпуску нужен сертификат.
- **Нельзя обновлять во время записи или стрима.** Окно предложит обновиться позже, если идёт запись.
- Конкретные имена файлов и настроек обновления (файл манифеста обновления, ключ подписи) я уточню по документации выбранного инструмента перед написанием кода.

## 7. Риски

- **Драйвер:** самая сложная часть. Нужны Visual Studio, WDK, тестовый режим Windows, а для выпуска другим людям EV-сертификат и подпись Microsoft. Без подписи драйвер работает только у разработчика.
- **Задержка и стабильность:** обработка блоками 128–256 сэмплов без щелчков, ресемплинг между устройствами с разной частотой.
- **Шумоподавление:** нейросеть нагружает процессор; проверить на вашей машине в реальной игре.
- **Звук на материнской плате:** качество и задержка зависят от драйвера Realtek. Если будут проблемы, на помощь придёт режим WASAPI Exclusive или ASIO4ALL.
